# ProofMesh 试点价值计分卡

> 目的：把“防越权、避免重复退款、失败可恢复、结果可审计”变成可在真实历史工单盲测中验收的指标。本文只定义口径、基线与目标；没有真实企业样本前，不填写财务收益或客户改善结果。

## 1. 谁会采用，为什么

| 采用者 | 当前断点 | ProofMesh 交付物 | 首个可验收结果 |
|---|---|---|---|
| Agent 平台团队 | 模型计划与底层副作用之间缺少逐次授权 | Action Passport、Gateway、角色 MCP | 未获精确合同的写调用不触达业务工具 |
| 客服 / 业务中台 | 重试、双写失败和人工审批可能造成重复退款或状态漂移 | 稳定 logical operation、reconcile-before-retry、Saga | 相同操作重试不重复退款；不确定状态停止自动重放 |
| 安全团队 | RBAC 只能证明“谁能用工具”，不能证明“这次能用哪些参数” | 租户 / tool / resource / arguments / context / budget 绑定 | 参数、工具、上下文任一漂移均 fail closed |
| 审计 / 合规团队 | 日志由执行方自证，难以重放业务终态 | 五用途签名材料、外部 Trust Bundle、钉住策略、Verifier | 仅用包外公开材料复算 Proof；篡改后失效 |

## 2. 正式试点 KPI

试点的决策是“是否允许进入下一阶段受控 sandbox / 小流量接入”，而不是证明一个漂亮的综合分。指标分成三类：

- **主结果 KPI（1–3 个）**：错误放行率、重复副作用率、可判定案例的安全终态率；任一失败都停止升级。
- **诊断驱动指标**：人工触达率、恢复时间、审计取证时长，用于解释为什么改善或退化，不单独作为成功结论。
- **护栏指标**：误阻断率、UNKNOWN 转人工率、p95/p99 延迟、数据缺失率；防止通过“全部拒绝”虚假改善安全指标。

先测现有流程基线，再冻结目标。没有客户基线时，只能采用下面的 provisional gate，不能虚构相对提升：错误放行和重复副作用观察值必须为 0，并报告 Wilson 95% 上界；所有上游 `UNKNOWN` 必须转人工且不得自动重派；误阻断、人工触达和延迟只报告，不用合成数据预设一个“行业标准”。

| KPI | 统一定义 | 数据源 | 当前可复验证据 | 试点验收方式 |
|---|---|---|---|---|
| 重复副作用率 | `同一 logical operation 产生的额外业务写次数 / logical operation 数` | 上游业务流水 + Gateway operation | AgentDojo 合同回放中 2,159 次同键重试无重复；独立进程 HTTP 合成盲测 0 / 240（Wilson 95% 上界 1.5754%） | 用脱敏历史工单重放，并按稳定 operation id 与支付流水对账 |
| 错误放行率 | `合同发生工具、参数、上下文或注册漂移后仍触达工具的次数 / 漂移尝试数` | Gateway deny audit + 上游调用日志 | 公开回放中工具 / 参数 / 上下文错配各 0 / 2,159；独立 HTTP 合成盲测参数漂移 0 / 240（Wilson 95% 上界 1.5754%） | 由红队生成漂移调用；错误放行必须为 0，报告 Wilson 95% 上界 |
| 审批前写副作用 | `WAITING_APPROVAL 时发生的写调用数` | workflow state + gateway receipts + 业务快照 | 高风险参考路径在等待态 refund 为空 | 冻结计划后并发审批与重试；审批前写调用必须为 0 |
| 可恢复终态率 | `故障后到达 COMPLETED / COMPENSATED 且业务不变量成立的案例数 / 上游状态可判定案例数` | workflow events + 业务快照 + Proof | 独立 HTTP 合成盲测可判定案例 180 / 180 完成、对账恢复或补偿（Wilson 95% 下界 97.9105%）；另有对账不确定 60 / 60 进入 `UNKNOWN_MANUAL` 且停止自动重派 | 在支付后、回执前、终结前等崩溃点注入故障；UNKNOWN 不计“自动成功” |
| 审计复算成功率 | `使用发布包外 Trust Bundle 与 pinned policy 验证为 VALID 的 Proof 数 / 可验证终态 Proof 数` | 独立 verifier report | 3 / 3 reference workflow 有效；篡改负例失效 | 审计方在隔离环境中仅使用公开材料复验，不读取运行时私钥 / DB |
| 控制面附加延迟 | Gateway 首次合法派发与缓存重放的 p50 / p95 / p99 | benchmark JSON | 本机首次合法 1.132 / 2.429 / 4.789 ms；缓存重放 0.404 / 0.709 / 1.278 ms | 固定硬件、并发和持久化配置后重测；本机数字不得当作跨机排名 |
| 人工触达率 | `进入职责分离的 Human 审批的工单数 / 总工单数`，按风险层级拆分 | workflow events | 只证明门禁可用，不声称已有企业改善 | 与现网规则 / 人工队列做 A/B 或离线盲测，避免用“越低越好”的单一目标 |
| 审计取证时长 | 从指定 workflow id 到导出完整任务 / 审批 / 执行 / 业务终态证据的人工耗时 | 操作录像 + 导出清单 | 尚无真实基线 | 同一批案例分别使用现行日志与 Proof 包复核，由不参与开发的审计者计时 |
| 误阻断率（护栏） | `ground truth 允许且业务前置条件成立、但被 ProofMesh 拒绝或停在非业务要求人工态的案例数 / ground truth 允许案例数` | blind label + denial audit + 人工复核 | 当前公开合同回放只证明 ground-truth tool call 接受，不等同真实业务误阻断率 | 由独立评审在揭盲后复核；不得通过“全部拒绝”换取零误放行 |
| UNKNOWN 转人工率（护栏） | `上游状态无法可靠判定且停止自动重放、进入人工队列的案例数 / 上游 UNKNOWN 案例数` | reconcile result + workflow terminal | 合成故障盲测 60 / 60 | 目标为 100%；同时报告其占全部案例比例，过高则说明上游对账能力不足 |
| 数据有效率（护栏） | `通过 closed schema、授权引用、标签分离与覆盖门禁的工单数 / 输入工单数` | pilot dataset validator | 导入器已实现；无外部数据结果 | 报告被拒字段/样本类别，不能静默丢弃困难案例 |

## 3. 不造假的价值换算

试点完成后，可用同一口径估算年度价值；提交初赛时只展示公式，不代入虚构客户数据：

```text
年度风险避免价值
= 年工单量 × 基线异常副作用率 × ProofMesh 相对降低比例 × 单次异常平均损失

年度审计效率价值
= 年审计案例数 × (基线取证时长 - Proof 复算时长) × 审计人力成本

年度运维效率价值
= 年异常案例数 × (基线恢复时长 - 受控恢复时长) × 业务中断单位成本
```

所有输入必须来自企业账务、工单和审计抽样；同时报告样本量、时间窗、置信区间与未被覆盖的异常类型。不能把 629-case 授权合同回放推导成客户 ROI，也不能把本机毫秒延迟推导成生产 SLA。

## 4. 两周最小试点

1. 选取 200–500 条脱敏退款历史工单，覆盖自动、人工审批、下游失败和重复重试。
2. 先记录现行流程的重复副作用、人工触达、异常恢复和取证时长基线。
3. 以 shadow mode 运行 ProofMesh：生成计划与 Passport，但不调用真实支付；对照现网最终结果。
4. 在支付沙箱启用受控写入，注入参数漂移、并发审批和五个崩溃窗口；UNKNOWN 必须停机转人工。
5. 由独立评审者从干净环境复验 Proof，并签署差异报告。
6. 只有达到预先约定阈值后，才讨论真实小流量接入与财务收益。

## 4.1 预注册与揭盲纪律

1. 在 labels 不可见时冻结代码 commit、策略摘要、数据 schema、主 KPI、护栏、统计方法和停止条件。
2. 先用独立 50 条 calibration set 排查接线错误；它不得计入最终 200–500 条盲测，也不得用于最终区间。
3. 盲测期间只允许修复基础设施故障；任何会改变业务决策的修改都必须新建版本并从头重跑。
4. 报告所有输入、拒绝、异常、人工覆盖和缺失，不能只选成功样例。
5. 比例同时给分子/分母与 Wilson 95% 区间；延迟/耗时给 p50/p95/p99 与硬件、并发、时间窗。
6. 只有数据方允许公开的聚合结果进入 PPT；原始案例、映射表和凭证永不进入发布包。

## 5. 当前可证与仍需外部完成

当前仓内可证：合同错配 fail closed、同键重试零重复、审批前零写、外部签名 assertion 的 Workflow / Gateway / 包外 Verifier 三重绑定、Saga 补偿恢复、三条 Proof 包外有效、240 条独立进程 HTTP 合成故障盲测与控制面本机延迟画像。

仍需外部完成：真实企业历史工单、现网基线、客户 / 审计者盲测、第三方支付与 CRM sandbox adapter、企业 IdP / 审批服务、第三方安全评估和生产 SLA。当前 240 条只是独立 OS 进程、独立数据库的确定性合成盲测，reference approval 也只是 synthetic issuer；两者均不是客户试点、企业身份或生产证据。
